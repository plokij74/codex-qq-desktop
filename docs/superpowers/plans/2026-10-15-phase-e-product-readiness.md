# Phase E：全部功能缺口补齐总计划（E1–E27）

**状态：规划，尚未实施。代码基线：`5b5a094`（D21 完成）。**

本版取代此前带具体日期、仅安排 E1–E5 的草案。按最新要求：**不排具体日期，不设工期承诺；将本次审计发现的缺失、部分实现和虚假入口全部分配到 E1–E27，按依赖决定实施顺序。**

本次只修改规划文档，不开始功能开发。阶段编号不是自动执行、读取凭据、安装依赖或进行外部写操作的授权。

## 一、范围与完成口径

### 1. 不再把高级缺口移到“以后再说”

PTY、OS 隔离、语义索引、子 Agent 续跑、会话导入、回滚、运行中压缩、插件平台、站点监控、定时任务、自动修复、桌面生命周期和云同步等，全部在本规划中有明确阶段。

同时区分三类，避免把历史上明确不做的功能误报为现有实现的 Bug：

- **A：已证实的断点或展示与行为不一致。** 必须修复现有链路。
- **B：已有基础版，但缺少完整能力。** 保留现有实现，再扩展，不从零重造。
- **C：原 MVP 非目标或本次纳入的完整产品能力。** 现在也安排实现；开工前冻结支持范围与真实外部条件，不能把未验证能力先写成已支持。

“全部”指本次审计及本规划覆盖表中的全部缺口，不声称已经穷尽所有软件可能具有的功能。后续发现的新缺口要登记并归入已有阶段或追加编号，不能无声遗漏。

### 2. 虚假入口必须两步关闭问题

1. **先止血：** 去掉假成功、假健康、假在线、假执行，明确演示/未接通状态。
2. **再做实：** 接入真实数据、执行、持久化和错误处理，完成端到端验收。

**隐藏按钮、改名、禁用、标“演示”只算止血，不算对应功能完成。** 本地模拟模式可以保留作为明确的离线测试模式，但不能计入真实模型/外部服务验收。

### 3. 已有能力不重复造轮子

核心 Agent、权限审批、Plan 后端、MCP OAuth/Tasks、词法索引、后台验证、验证 DAG、worktree、PR 审查/修复/复审/追踪已经存在。后续阶段均在这些能力上补齐边界和端到端链路。

当前“已安排”路由已改为真实工程中心；未使用的旧定时常量不等于当前 UI 正在伪造任务执行。依据：[工程中心入口](<../../../src/renderer/app.js#L3976-L3978>)、[D21 实施记录](<2026-10-12-phase-d21-pr-audit-tracking.md>)。

### 全程前置约束

- E2 就定义模型内容投影、附件身份、执行事件、用量归因和资源预算字段；E4/E11 是产品能力完成阶段，不意味着此前可以无能力判断、无预算运行。
- 文件授权、链接/路径复验、网络 SSRF 防护、大小/像素/时间限制、取消与日志脱敏随各功能一起交付。E3 的 OS 隔离不是此前允许不安全实现的理由。
- E1 就核对真实通信目标和官方接口是否存在；E4 的 AI 助手不能借此伪装成真实 QQ 联系人。E26 有独立可行性门，不承诺不存在的官方能力。
- 编号是推荐整合顺序；可并行做独立模块、测试和规格，但不能跳过明确的依赖门。每阶段都要测试，不能全部拖到 E27。

## E2：统一消息、Plan 状态与工具轨迹持久化

前置：E1。

- 定义版本化消息、附件引用、文本/模型/存储投影、Plan 版本及迁移规则；先统一供 E9/E10 共用的任务标识、归属、取消与事件契约。贯穿 UI、IPC、模型请求、持久化、compact、export、usage，禁止以 `String(parts)` 兼容结构化内容。
- Plan 脱离临时 `chatRun`：正常生成结束、切换会话、重绘后仍有完整计划和批准/拒绝入口。
- 主进程保持执行权威；计划绑定发送者、会话、项目、版本与约定的工作区当前性。批准/启动状态转换防重复，启动失败后明确是否可重试。
- 恢复历史可见性不等于恢复授权。旧计划、撤权、项目变化、部分执行后崩溃不得重放副作用；缺少当前授权时显示需重新确认。
- 保存有界、脱敏的工具时间线、审批结论、验证结果、子任务/文件变更引用；工具调用与结果成对，重载可回看，但不能凭历史“允许”自动执行新操作。
- 明确附件来源、归属、缺失、删除、去重、缓存清理、导出原件策略与预算字段；旧版读取失败保留原数据。

验收：finalize 后仍可批准；重复点击/迟到事件不重复执行；切换项目和重启不会串会话或恢复旧权限；历史轨迹、附件引用和旧数据迁移完整；共用任务标识/取消/事件契约通过状态转换测试。

## E3：权限、OS 隔离与秘密管理

设计规格见 [E3 spec](docs/superpowers/specs/2026-10-16-phase-e3-permissions-os-isolation-secrets-design.md)。实施计划见 [E3 plan](docs/superpowers/plans/2026-10-16-phase-e3-permissions-os-isolation-secrets.md)。
前置：E2。

- 在既有应用层权限 Gate 上增加明确的执行策略与 OS 级隔离后端；分别声明文件、网络、进程、环境变量和资源边界。
- Windows 为首要验证平台。用实际拒绝读写/出站/进程逃逸测试证明边界；仅设置 cwd、黑名单、Job Object 或 renderer `sandbox:true` 不能标为完整 OS 沙箱。
- 统一文件/目录能力、路径和链接复验、执行范围、子进程树清理；项目授权不自动覆盖其他目录或网络目标。
- 秘密由主进程受控存储；子进程只接收获准的必要环境，不默认继承全部密钥。日志、导出、模型上下文和插件权限不得泄漏凭据。
- 隔离不可用时明确拒绝相关强隔离功能；如提供宿主执行模式，必须清楚区分并独立确认，不能静默降级仍显示“已隔离”。

验收：越界读取/写入/网络/环境访问被真实阻止；撤权、取消、超时后子进程和资源正确回收；现有低风险工具不被无意破坏。

## E4：模型能力管理与真实助手/好友会话

前置：E2、E3。

- 建立适配器与能力表，明确文本、tools、视觉、流式、上下文与 usage 支持；现有 OpenAI 兼容能力保留，其他承诺支持的协议逐个实现和验收，不能只增加下拉选项。
- 模型切换、错误、兼容回退保持语义一致；不支持图片/tools 时明确拒绝或由用户选择降级，不静默伪装成功。
- 将模拟好友分清为“AI 助手角色”和“真实联系人”。AI 角色可配置模型、提示词、知识范围、项目和工具权限，通过真实模型链路运行，具备独立历史与取消机制。
- AI 角色状态显示模型/配置可用性，不冒充真人在线；真实联系人/通话由 E26 交付。
- API 配置、认证失败、限流、连接诊断与安全凭据更新有真实状态；本地模拟始终明确标注。

验收：每个列为支持的适配器有请求级与真实端点测试；非 Codex 的助手会话不再返回固定“收到”话术；能力切换不丢草稿或偷偷外发替代请求。

## E5：文本附件与受控附件存储

前置：E2、E3、E4。

- 从普通文件名/大小展示升级为真实内容导入。先覆盖 UTF-8/BOM 文本、代码、Markdown、JSON、CSV 等，验证编码和实际内容类型。
- 主进程拥有附件记录与受控字节/文件能力，renderer 使用不透明引用；用户选择的外部文件与项目 `@引用`保留各自授权来源。
- 发送前预览实际内容、截断信息和目标模型；发送时重新校验归属、权限与预算。取消/移除附件不得继续外发。
- 对单文件、数量、总字节、提取字符、上下文与总缓存设上限。加密持久缓存不可用时明确内存模式，禁止静默明文或无限 localStorage base64。
- 缺失、损坏、过期、去重和删除有可见状态；缓存清理只处理应用自有副本，不删除用户原文件。
- 同步压缩、导出、用量、会话切换、重试与旧数据兼容；默认导出不携带原件或本机隐私路径，显式原件导出在 E12 补齐。

验收：模型请求实际含用户确认的文件内容；超限/二进制伪装/错误引用/链接变化安全失败；拒绝和取消不外发；原文件及旧数据不受损。

## E6：图片多模态

前置：E4、E5。

- 支持真实静态图像输入，向适配器生成图像与文本 content parts，而非 Markdown/base64 文本。
- 验证 MIME、解码格式、像素、尺寸、单图/多图/整次请求上限，计算编码膨胀后的预算。
- 多图与文字顺序、流式/非流式、模型切换、重试和取消保持一致；不支持图像时不给“已经看图”的假象。
- compact 保存引用和已有文字结论，不把原始 base64 交给文本摘要；子 Agent/记忆/PR 流程只收到明确获准的图像或有标识的文本投影。
- 图片 usage 区分供应商实报和未知/估算，不把 base64 字符数当精确 token 账单。

验收：请求级断言存在真实图像 parts；真实视觉模型识别事先准备的图像细节；不支持、损坏、超限、缓存缺失和隐私保护都有反向测试。

## E7：复杂文档、OCR、压缩包与媒体解析

前置：E3、E5、E6。

- 按独立适配器实现 PDF、Word/Excel/PowerPoint 内容提取；保留页码、工作表/单元格、幻灯片等来源，不把文件名当内容。
- 扫描文档/图片 OCR 保留识别置信度和来源；表格、布局或文字无法可靠读取时标明局限，不编造内容。
- 压缩包先列清单再授权选择；阻止路径穿越、解压炸弹、递归/数量/容量失控，不自动执行其中脚本。
- 音频转写、视频音轨/关键帧提取分别设置能力、预算、时长与隐私提示；不把附件解析冒充实时语音视频通话。
- 解析在受限 worker 中执行，落实依赖安全、许可证、加密/损坏文件、宏与外部链接处理；不运行文档宏、不自动访问嵌入远端资源。
- 建立格式×样本×提取准确性矩阵，只有经过验证的组合进入“支持”列表。

验收：每种承诺格式都有正常/损坏/恶意/超限样本、真实提取结果和来源定位；拒绝不污染工作区、不泄漏数据或启动外部程序。

## E8：关键词 Web Search 与真实站点管理

前置：E3、E4、E5。

- 在已有 `web_fetch` 之外加入真正的关键词搜索适配器，支持结果、标题、URL、摘要、来源与进一步读取；无结果、限流和供应商失败清楚显示。
- 搜索/抓取复用网络授权、域名规则、DNS/重定向复验和大小/超时限制；网页与搜索摘要一律是不可信数据，不取得工具权限。
- 站点页改为用户网址增删改、分组/备注、导入导出、真实手动读取/检查；清除固定示例作为真实生产站点的展示。
- 显示“未检测/最近检查结果与时间”，不能用一次读取成功宣称持续健康；连续监测由 E18 交付。
- 搜索供应商、凭据与费用可管理；站点收藏不自动授权内网访问，也不在启动时偷偷抓取。

验收：真实关键词搜索返回可核验来源；站点数据持久化，检查结果由请求产生；拒绝/取消不出站，重定向到受限地址被拒绝。

## E9：PTY 交互终端

前置：E2、E3。E2 先定义供 E9/E10 共用的任务标识、取消与事件接口；E9 不等待 E10 完整交付。

- 保留一次性命令工具，同时增加真正 PTY：持续 shell、stdin、窗口尺寸、ANSI 输出、Ctrl+C、退出码、会话关闭与进程树管理。
- 终端按会话/项目归属，cwd 和状态可持续；切换页面不丢输出或把输入送到别的进程。
- 交互密码与秘密输入不进入模型/日志；输出有界，背压、粘贴确认、超时与长命令行为明确。
- Windows shell/编码与 native 模块打包有实际验证；隔离模式与宿主模式明确区分，不将所有终端自动置于高权限。

## E21：真实插件平台与四个示例功能

### 运行平台

### 四个名字逐项交付

- **Code Review：** 复用已有 PR AI 审查；加明确的自动触发策略、提交去重和报告回流。自动审查不等于自动发布评论，远端写仍受独立授权控制。
- **Doc Search：** 使用 E15 的真实文档/语义索引，能搜索并引用具体文档位置，不仅把用户问题再转发给聊天。

- **Migrate Guard：** 对选定数据库的迁移与 schema 做真实静态检查、差异预览、隔离试跑/回滚验证和风险报告；默认不直接跑生产迁移，未连接不能返回“结构确认没问题”。

验收：四项各有真实输入、执行链路、输出证据、错误/取消/权限场景；缺一项就不能把“插件页做实”整体勾选完成。

- 旧审批、工具能力、待执行操作、活跃终端/MCP 会话不能变成另一设备的有效授权；同步历史不等于同步执行权。
- 密钥/账号恢复方案真实可用；服务端故障不破坏本地数据，不能把冲突静默覆盖为最新一份。

验收：两台真实客户端的会话/PR 草稿往返、离线修改、同步冲突、删除、撤销与恢复测试通过；不同设备不会互相执行历史任务或泄漏本机能力。

## E26：真实联系人、文件通信与语音视频

前置：E3、E4、E7、E10、E25；目标平台与官方接口可行性在 E1/E4 前置核对。

- 明确产品究竟接入哪个合法平台/官方 SDK，或提供自己的通信服务；QQ 风格皮肤不代表有 QQ 私有协议能力。
- 实现真实联系人/身份、在线状态、消息收发、回执、失败重试与屏蔽；AI 角色身份和真人身份不能混淆。
- 真实文件传输有对端、进度、校验、取消与隐私/保存位置控制；本地附件发模型不等于发送给联系人。
- 语音输入/输出、音视频通话及需要的转写分别实现，处理麦克风/摄像头权限、对端同意、设备切换、断线、费用与录制提示。
- 不逆向或绕过私有协议/风控，不窃取客户端凭据。若官方接口不开放，记录真实阻断并向用户提出合法替代平台选择，不能用模拟聊天勾选完成。

验收：至少两端真实身份的消息/文件/语音视频场景通过；真实在线/离线与失败状态可信，权限拒绝不采集或发送媒体。

## 七、实施和状态规则

1. 每个阶段开工前再写该阶段的实现拆解：文件、接口、RED/GREEN 测试、迁移、依赖/许可证、安全、回退与真实验收；总规划不提前制造空壳模块。
2. 技术路线沿用 Electron/Node/现有 renderer。PTY、解析器、LSP、OCR、媒体、同步等需要新依赖或服务时，单独说明原因与风险；不再用“一律不准加依赖”使已安排功能无法实现。
3. 同一份主进程/渲染状态由一个整合者负责；独立模块可并行，但共享消息/权限契约先统一，防止多个实现互相覆盖。
4. 每阶段必须同时完成 UI、业务、状态/存储、错误/取消、权限与验收，不能只做按钮或后端函数。
5. 有缺资源/平台限制时保留明确阻断和替代方案，不能自行删项、隐藏后宣称完成。任何范围裁剪须用户明确同意并留痕。
6. 不改写旧 D 阶段记录，不清理无关既有文件；新增阶段记录实际实现与测试结果。
