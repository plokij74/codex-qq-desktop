# Phase D21：多轮修复追踪

日期：2026-10-12。对应 [实施记录](../plans/2026-10-12-phase-d21-pr-audit-tracking.md)。

## 已确认范围

PR 详情提供「问题列表＋轮次详情」，工程中心提供报告入口。每份原始 D17 报告独立追踪，问题身份为 auditRef + findingId，不跨报告归并、不增加人工处置状态。沿用 D18–D20 手动操作；浏览与跳转不会启动修复、验证、复审或远端写入。

问题保留原报告顺序，展示最近完成复审的 AI 判断、理由及提交。最近按创建时间、引用 ID 排序，失败尝试不覆盖结论。PR 的仓库、范围、分支、head/base、merge-base 或描述发生变化时结论过期；远端读取失败为当前性未核实。旧结论继续显示，但不计入当前已解决数量。没有完成复审的原问题显示尚未复审。

每个实际修复任务计一个轮次，来源预览不计数。轮次包含生成、复验、交付及所有复审记录；按父复审显示续修关系，同父修复为并列分支。轮次编号仅代表显示顺序，不代表必然串行。失败、取消、中断、无改动与不确定交付保留。

## 聚合与接口

PrAuditTracking 从既有 D17 报告、D18/D20 来源、D13 修复任务、D5 校验过的结果摘要和 D19 复审历史构建临时读模型，不新增持久化文件、格式迁移或模型工具。

| IPC（engineering:pr-audit:tracking:） | 输入 | 输出 |
| --- | --- | --- |
| list | projectBindingId、可选 prNumber | 项目 key、报告摘要、来源可用性、存储状态 |
| get | projectBindingId、auditRef | 原问题、轮次关系、复审摘要、统计、核对时间、缺失提示 |

接口沿用 auditRequest 的 sender 所有权、绑定校验、取消及迟到响应保护。Renderer 不能提供路径、SHA、结论或父链。列表只读取本地 origin 身份及历史；详情对同一 PR 查询一次远端快照并共享当前性判断。GitHub CLI 的 localOnly 仓库解析只执行本地 Git 读取，不访问 GitHub。

聚合先按规范项目、origin 仓库和项目相对范围过滤，再按原报告与 PR 关联。引用缺失、关联冲突及循环显示历史不完整，不猜测父链；修复任务缺失的复审单独展示，不凭复审捏造轮次。没有原报告时仍可展示有效历史片段。交付状态来自已有校验的结果摘要；不确定推送不推断为已交付。

## 界面与生命周期

默认打开最近完成的报告，保留报告选择、展开项、焦点和滚动。刷新立即将当前性标为未核实；页面、绑定或请求代次改变后丢弃旧响应。既有审查、复审、修复事件触发刷新，PR 更新操作完成后刷新追踪。工程中心只加载本地报告摘要。

原发现、复审、修复详情和结果卡均复用已有入口。追踪不复制代码片段、完整提示、验证输出或审批能力；正文不进入 localStorage、聊天、记忆、导出或 Hooks。存储降级、不可用历史显示提示。关闭/合并的 PR 保留历史展示，后续动作仍由现有流程检查资格。

## 验收

单元与集成覆盖多轮部分续修、分支、同时间排序、源缺失、循环、PR 变化、离线、失败任务、跨报告/仓库/项目隔离、IPC 注入、迟到响应、转义、导航无副作用。Electron 离线冒烟基于真实临时 Git，完成 D18 交付与连续两轮 D20 修复后验证追踪、导航、刷新和 1100×720 / 900×580 布局。完整测试、脚本语法及 diff 检查通过后记录实际结果。
