# Phase E1：基础断点修复与虚假展示止血设计规格

日期：2026-10-15。对应 [实施规划](../plans/2026-10-15-phase-e-product-readiness.md) 与 [不稳定用例跟踪记录](../plans/2026-10-15-e1-flaky-test-tracking.md)。

## 一、设计目标与定位

Phase E1 作为全功能补齐工程（E1–E27）的奠基阶段，目标是彻底清除前端直接操作中的致命代码断点，消除所有欺骗性 UI 伪装，并建立后续关键能力闭环的验收基线：
1. **零崩溃**：消除因代码语法/变量错漏导致的运行时致命异常（G01）。
2. **状态保真**：设置项与数据状态在读写、持久化与异常恢复中保持数值一致性与非破坏性（G02）。
3. **交互闭环**：关键操作按钮具备真实调度执行与防并发能力，不留空响按钮（G03）。
4. **诚实展示（止血）**：所有未接入真实底层后端的模块明确标识为“示例/本地演示/待后续接入”，严禁在无真实能力支撑下显示虚假的“在线”、“健康”、“已启用”或“文件已读取”（G09）。
5. **缺陷固化**：为当前无法在纯前端止血层面独立解决的架构缺陷（如 Plan 审批持久化 G04、Git 锁并发不稳定 G43）建立可复现的行为测试与问题跟踪档案，交由对应阶段闭环。

## 二、详细设计与规范

### 1. MCP OAuth 纯净拷贝与 Prompt 命令分发（G01）

- **问题根因**：`cloneMcpOAuth()` 函数原实现中错误拼入了斜杠命令的分发判断代码，且直接引用了未声明的局部变量 `lower` 与 `cmd`，导致调用时产生 `ReferenceError: lower is not defined` 运行时崩溃。
- **设计规范**：
  - `cloneMcpOAuth(oauth)` 职责单一化：仅执行严格的纯数据深拷贝与字段清理（支持 `clientId`、`clientSecret`、`authorizationUrl`、`tokenUrl`、`scopes`、`redirectUri` 等字段），绝不掺杂任何命令路由逻辑。
  - 斜杠命令归位：在 `handleSlashCommand(text)` 顶层路由中正式接通 `/mcp-prompts` 与 `/mcp-prompt`，调用 MCP 客户端能力列出及插入预设提示词。

### 2. 设置项数值保真与存储容灾（G02）

- **最大轮数合法零值（0 = 无限制）**：
  - 核心原则：`0` 是受支持的合法业务数值（表示不限制最大自动轮数），不能在任何逻辑分支中因 falsy 隐式转换回退为默认值 `8`。
  - 读取规范：`settings.maxAgentTurns ?? 8`（使用空值合并运算符替换逻辑或运算）。
  - 写入规范：表单提交时，空字符串解析为默认值 `8`，合法非负数字（包括 `0`）保留原数值，非法输入回退为 `8`。
- **空项目与损坏数据保护**：
  - 用户清空项目时持久化的 `projects: []`，在 `loadState()` 反序列化时必须判定为合法配置保留为空数组，不可与“从未初始化”混淆而强制填充默认项目。
  - 当读取到无效 JSON 格式导致解析异常时，严禁静默覆盖损坏文件。必须首先将原始数据备份至 localStorage 的 `codex-qq-corrupted-${Date.now()}` 键中，向用户弹出持久性 Toast 警告，再安全回退至默认配置。

### 3. 模态弹窗“创建并开始”真实触发与防重（G03）

- **行为规范**：
  - 点击“创建并开始”按钮时，检查提交防重状态 `taskModalSubmitting`。若处于提交中，立即阻断。
  - 校验任务标题与说明：
    - 若说明（brief）非空：创建任务会话后，直接调用 `sendMessage(activeSessionId, brief)` 触发 Agent 运行，进入真实的流式处理循环。
    - 若说明为空：创建任务草稿，关闭弹窗，并自动聚焦输入框提示用户输入。
  - 遇忙或失败保护：若当前已有活跃 Agent 正在生成，或主进程拒绝创建，弹出提示，保留弹窗中用户已填写的文本，不得强行关闭弹窗或丢失用户输入。

### 4. Plan 审批断点回归基线（G04）

- **现状记录**：在当前版本中，当模型 Plan 输出完成并触发 `finalizeChatRun()` 时，由于审批状态只维护在临时内存的 `chatRun` 对象中，重绘或刷新会导致审批按钮不可用甚至卡片丢失。
- **设计边界**：E1 阶段不凭空造一套半吊子的内存妥协，而是在 `tests/e1-plan-approval-gap.test.js` 中固化该行为特征并建立回归测试，留待 **E2（统一消息、Plan 状态与工具轨迹持久化）** 从主进程状态机与消息模型层面彻底闭环。

### 5. 虚假展示止血（G09）

- **插件模块**：页面增加醒目标签与说明横幅：“插件后端运行时尚未接通（待 E21 实现），当前开关仅作为本地配置预览”。点击开关时明确提示配置已保存但运行时未激活。
- **站点管理**：去除无后端探针支持的伪造 `healthy` 绿标与 `degraded` 黄标，统一标识为“示例配置”，明确标注文档“未接入持续健康监测（待 E8/E18 实现）”。
- **好友与通讯录**：通讯录中的 Randy Lu 与 Maya 标注为“模拟角色”，去除伪造的“在线/离开”实时状态；自动回复明确附带“（模拟好友：真实通信待 E26 接入）”。
- **附件上传**：用户拖拽或选择非图片普通文件时，前端提示横幅明确告知：“当前版本仅记录元数据，模型暂无法直接读取非图片文件内容（待 E5/E7 实现完整解析）”，防止误导用户以为模型已理解其专有格式附件。
- **初始预置内容**：初始任务与 KV 结构分析话术明确标记 `【示例】` 前缀，不冒充真实代码分析结果。

### 6. 不稳定用例跟踪与隔离（G43）

- **跟踪规范**：建立 [E1 不稳定用例跟踪日志](../plans/2026-10-15-e1-flaky-test-tracking.md)，详细记录 `tests/remote-ci-delivery.test.js` 在 Windows 多测试进程并发执行时因 Git 临时 worktree 索引锁竞争引起的 `PR_UPDATE_TREE_MISMATCH` 现场。
- **治理原则**：绝不通过放宽断言、删除校验或吞掉错误来虚假呈现全绿；保持底层真实报错，留待 **E19（PR 更新与多轮复检闭环）** 引入进程级互斥文件锁彻底解决。

## 三、验收标准与测试套件

| 验证项 | 对应模块 | 验证方法与验收基线 |
| --- | --- | --- |
| MCP OAuth 深拷贝 | `app.js` | `cloneMcpOAuth` 返回完整副本，不抛 `ReferenceError`，`/mcp-prompts` 正确路由 |

| 虚假展示止血 | `app.js` | 插件、站点、好友、附件、预置数据全部展示诚实提示 |
| 全量回归测试 | `tests/` | 41 项核心回归用例全绿；不稳定用例归档留痕 |
